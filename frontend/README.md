# سامانه مدیریت درخواست‌های سازمانی

یک سامانه تحت وب برای ثبت، مشاهده، جستجو، فیلتر و مدیریت درخواست‌های سازمانی که با هدف پیاده‌سازی یک رابط کاربری فارسی، راست‌چین و واکنش‌گرا توسعه داده شده است.

این پروژه با استفاده از Next.js و TypeScript پیاده‌سازی شده و برای دریافت و ارسال اطلاعات با یک REST API مبتنی بر FastAPI ارتباط برقرار می‌کند.

## معرفی پروژه

سامانه مدیریت درخواست‌های سازمانی با هدف ساده‌سازی فرآیند ثبت و پیگیری درخواست‌ها طراحی شده است.

کاربران می‌توانند درخواست‌های جدید ثبت کنند، اطلاعات درخواست‌های قبلی را مشاهده و ویرایش کنند و از طریق جستجو و فیلتر، درخواست موردنظر خود را پیدا کنند.

تمرکز اصلی در توسعه این پروژه بر موارد زیر بوده است:

- طراحی رابط کاربری ساده و قابل استفاده
- رعایت اصول تجربه کاربری (UX)
- پیاده‌سازی ساختار کامپوننت‌محور و قابل استفاده مجدد
- ارتباط با REST API
- مدیریت حالت‌های مختلف رابط کاربری
- پشتیبانی از زبان فارسی و چیدمان راست‌چین (RTL)
- طراحی واکنش‌گرا برای اندازه‌های مختلف صفحه‌نمایش

## امکانات پیاده‌سازی‌شده

### ۱. داشبورد

- نمایش خلاصه وضعیت درخواست‌ها
- دریافت آمار از API
- نمایش تعداد درخواست‌ها بر اساس وضعیت
- نمایش آخرین درخواست‌های ثبت‌شده
- امکان انتخاب وضعیت از طریق کارت‌های آماری و مشاهده درخواست‌های مرتبط

### ۲. مدیریت درخواست‌ها

- دریافت و نمایش فهرست درخواست‌ها از API
- مشاهده جزئیات هر درخواست
- ثبت درخواست جدید
- ویرایش اطلاعات درخواست‌های ثبت‌شده
- نمایش وضعیت و اولویت هر درخواست
- نمایش تاریخ ثبت درخواست
- دسترسی به صفحه جزئیات و ویرایش از طریق جدول درخواست‌ها

### ۳. جستجو و فیلتر

- جستجو بر اساس عنوان درخواست
- اعمال تأخیر ۴۰۰ میلی‌ثانیه‌ای (Debounce) برای جلوگیری از ارسال درخواست API با هر بار فشردن کلید
- فیلتر بر اساس وضعیت:
  - جدید (New)
  - در حال بررسی (In Progress)
  - تکمیل‌شده (Completed)
- فیلتر بر اساس اولویت:
  - کم (Low)
  - متوسط (Medium)
  - زیاد (High)
- امکان استفاده هم‌زمان از جستجو و فیلترها
- امکان پاک کردن متن جستجو و فیلترها
- نمایش پیام مناسب در صورت پیدا نشدن درخواست
- بازگشت به صفحه اول هنگام تغییر جستجو یا فیلترها

تمام عملیات جستجو و فیلتر از طریق پارامترهای API انجام می‌شوند و صرفاً به داده‌های دریافت‌شده در فرانت‌اند محدود نیستند.

### ۴. فرم ثبت و ویرایش درخواست

- پیاده‌سازی فرم با React Hook Form
- اعتبارسنجی اطلاعات با Zod
- نمایش خطاهای اعتبارسنجی زیر فیلدهای مربوطه
- امکان ثبت درخواست جدید
- امکان ویرایش اطلاعات درخواست
- نمایش اعلان موفقیت یا خطا با Toast
- جلوگیری از ارسال فرم در حالت بارگذاری

**ذخیره خودکار پیش‌نویس فرم (Auto Save)**

برای جلوگیری از از دست رفتن اطلاعات واردشده توسط کاربر، قابلیت ذخیره خودکار پیش‌نویس فرم ثبت درخواست با استفاده از LocalStorage پیاده‌سازی شده است.

اطلاعات فرم هنگام تغییر، در مرورگر ذخیره می‌شوند تا در شرایطی مانند موارد زیر قابل بازیابی باشند:

- خروج ناخواسته کاربر از صفحه
- بستن یا بارگذاری مجدد مرورگر
- قطع شدن اینترنت هنگام تکمیل فرم
- بازگشت مجدد کاربر به صفحه ثبت درخواست

با ورود مجدد به صفحه ثبت درخواست، اطلاعات ذخیره‌شده بازیابی می‌شوند و کاربر می‌تواند تکمیل فرم را از همان مرحله ادامه دهد.

پس از ثبت موفق درخواست، پیش‌نویس ذخیره‌شده پاک می‌شود.

این قابلیت باعث کاهش احتمال از دست رفتن اطلاعات و بهبود تجربه کاربری در فرآیند ثبت درخواست می‌شود.

**نکته:** اطلاعات پیش‌نویس در LocalStorage مرورگر ذخیره می‌شوند و به سرور ارسال نمی‌شوند. در نتیجه، قطع اینترنت به‌تنهایی باعث از بین رفتن اطلاعات ذخیره‌شده نخواهد شد؛ اما با پاک شدن داده‌های مرورگر، پیش‌نویس نیز حذف می‌شود.

### ۵. مدیریت وضعیت‌ها و خطاهای رابط کاربری

برای ایجاد تجربه کاربری مناسب، حالت‌های مختلف در رابط کاربری در نظر گرفته شده‌اند:

- Loading: نمایش Skeleton هنگام دریافت اطلاعات
- Error: نمایش پیام خطا در صورت بروز مشکل در ارتباط با API
- Empty: نمایش پیام مناسب در صورت نبود درخواست
- Success: نمایش اعلان موفقیت پس از انجام عملیات
- Validation: نمایش خطاهای اعتبارسنجی فرم

همچنین برای خطاهای مهم API پیام‌های اختصاصی در نظر گرفته شده‌اند.

### ۶. مدیریت هم‌زمانی و نسخه اطلاعات

در فرآیند ویرایش درخواست از فیلد `version` و پارامتر `expected_version` استفاده شده است.

در صورت تغییر درخواست توسط کاربر دیگر و دریافت پاسخ `409 Conflict`، پیام مناسبی به کاربر نمایش داده می‌شود و امکان بارگذاری مجدد اطلاعات وجود دارد.

همچنین خطای `503 Service Unavailable` به‌صورت جداگانه مدیریت شده است.

## نحوه راه‌اندازی پروژه

برای اجرای کامل پروژه باید بک‌اند و فرانت‌اند را به‌صورت جداگانه اجرا کنید.

### ۱. دریافت پروژه

ابتدا مخزن پروژه را دریافت کنید:

```bash
git clone YOUR_REPOSITORY_URL
```

سپس وارد پوشه اصلی پروژه شوید:

```bash
cd management-system
```

### ۲. راه‌اندازی بک‌اند

بک‌اند پروژه با Python و FastAPI پیاده‌سازی شده است.

برای جلوگیری از تداخل نسخه کتابخانه‌ها با سایر پروژه‌های پایتون، از یک **محیط مجازی پایتون (Virtual Environment)** استفاده شده است.

محیط مجازی باعث می‌شود وابستگی‌های موردنیاز این پروژه به‌صورت جداگانه نصب و مدیریت شوند و روی محیط اصلی Python سیستم تأثیری نداشته باشند.

#### مرحله اول: ساخت محیط مجازی

در مسیر اصلی پروژه دستور زیر را اجرا کنید:

```powershell
py -m venv .venv
```

با اجرای این دستور پوشه `.venv` ساخته می‌شود.

#### مرحله دوم: فعال‌سازی محیط مجازی

در PowerShell دستور زیر را اجرا کنید:

```powershell
.\.venv\Scripts\Activate.ps1
```

پس از فعال‌سازی، معمولاً نام محیط مجازی یعنی `(.venv)` در ابتدای خط ترمینال نمایش داده می‌شود.

#### مرحله سوم: نصب وابستگی‌های بک‌اند

با فعال بودن محیط مجازی، دستور زیر را اجرا کنید:

```powershell
python -m pip install -r requirements.txt
```

این دستور کتابخانه‌های موردنیاز بک‌اند را نصب می‌کند.

#### مرحله چهارم: اجرای سرور بک‌اند

از مسیر اصلی پروژه دستور زیر را اجرا کنید:

```powershell
python -m uvicorn app:app --reload --host 127.0.0.1 --port 8000 --app-dir .\mock-api
```

در صورتی که سرور با موفقیت اجرا شود، API روی آدرس زیر در دسترس خواهد بود:

```text
http://127.0.0.1:8000
```

مستندات و امکان تست endpointهای API نیز از طریق آدرس زیر در دسترس است:

```text
http://127.0.0.1:8000/docs
```

**نکته:** برای اجرای مجدد بک‌اند در دفعات بعد، نیازی به ساخت دوباره محیط مجازی یا نصب مجدد کتابخانه‌ها نیست. کافی است محیط مجازی را فعال و سرور را اجرا کنید.

### ۳. راه‌اندازی فرانت‌اند

یک ترمینال جدید باز کنید و وارد پوشه فرانت‌اند شوید:

```powershell
cd frontend
```

ابتدا وابستگی‌های پروژه را نصب کنید:

```powershell
npm install
```

سپس فایل `.env.local` را در پوشه `frontend` ایجاد کنید و آدرس بک‌اند را در آن قرار دهید:

```env
API_SERVER_URL=http://127.0.0.1:8000
```

در نهایت فرانت‌اند را اجرا کنید:

```powershell
npm run dev
```

برنامه از طریق آدرس زیر در مرورگر قابل مشاهده خواهد بود:

```text
http://localhost:3000
```

**نکته مهم:** برای اجرای کامل سامانه، هر دو سرور بک‌اند و فرانت‌اند باید هم‌زمان در حال اجرا باشند.

## اتصال به API

ارتباط فرانت‌اند با بک‌اند از طریق Axios و سرویس‌های مجزا مدیریت شده است.

برای جداسازی منطق ارتباط با سرور از کامپوننت‌های رابط کاربری، عملیات مربوط به درخواست‌ها در فایل سرویس اختصاصی قرار گرفته‌اند.

endpointهای اصلی مورد استفاده:

| متد HTTP | مسیر                 | کاربرد                  |
| -------- | -------------------- | ----------------------- |
| GET      | `/api/stats`         | دریافت آمار داشبورد     |
| GET      | `/api/requests`      | دریافت فهرست درخواست‌ها |
| GET      | `/api/requests/{id}` | دریافت جزئیات درخواست   |
| POST     | `/api/requests`      | ثبت درخواست جدید        |
| PATCH    | `/api/requests/{id}` | ویرایش درخواست          |

در endpoint دریافت فهرست درخواست‌ها، پارامترهای زیر پشتیبانی می‌شوند:

| پارامتر     | کاربرد                   |
| ----------- | ------------------------ |
| `q`         | جستجو بر اساس عنوان      |
| `status`    | فیلتر وضعیت              |
| `priority`  | فیلتر اولویت             |
| `page`      | شماره صفحه               |
| `page_size` | تعداد درخواست در هر صفحه |

نمونه درخواست:

```http
GET /api/requests?q=دسترسی&status=new&priority=high&page=1&page_size=10
```

## مدیریت وضعیت‌ها و خطاها

در پروژه تلاش شده است وضعیت‌های مختلف ارتباط با API به‌درستی مدیریت شوند.

برای مثال:

- هنگام دریافت اطلاعات، وضعیت Loading نمایش داده می‌شود.
- در صورت دریافت پاسخ ناموفق از سرور، پیام خطای مناسب نمایش داده می‌شود.
- در صورت نبود اطلاعات، حالت Empty نمایش داده می‌شود.
- پس از ثبت یا ویرایش موفق، پیام موفقیت نمایش داده می‌شود.
- در صورت بروز خطای اعتبارسنجی، خطا در کنار فیلد مربوطه نمایش داده می‌شود.
- در صورت بروز خطای تعارض نسخه اطلاعات، پیام اختصاصی برای کاربر نمایش داده می‌شود.

## طراحی واکنش‌گرا

رابط کاربری با رویکرد Responsive طراحی شده است تا در اندازه‌های مختلف صفحه‌نمایش قابل استفاده باشد.

اندازه‌های هدف طراحی:

- موبایل: 360px
- تبلت: 768px
- دسکتاپ: 1440px

همچنین موارد زیر در طراحی رعایت شده‌اند:

- پشتیبانی از زبان فارسی
- رعایت چیدمان راست‌چین (RTL)
- نمایش مناسب جدول‌ها در صفحه‌های کوچک
- تنظیم ساختار منو و محتوای داشبورد متناسب با اندازه صفحه
- استفاده از چیدمان انعطاف‌پذیر برای فرم‌ها و فیلترها
